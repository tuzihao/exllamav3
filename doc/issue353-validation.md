# EXL3 issue #353 最小修复验证

2026-10-22。基于 EXL3 0.0.37，保留原量化实现，显式开启推理补丁。

本次修复的目标是相同计算路径重复运行的非确定性。S0 和完整的 S1 seed 0 均通过本次重复性检查；batch64 与单条一致性仍未通过原门槛，不放行正式评测。

| 已保存的比较 | S0 | S1 seed 0 |
|---|---:|---:|
| 原生单条重复最大目标 logprob 差 | 2.106085 | 0.546925 |
| 修复后单条重复最大差 | 0 | 0 |
| 修复后 batch64 重复最大差 | 0 | 0 |
| 修复后跨 batch 最大差 | 2.049856 | 1.437473 |
| 跨 batch 超过原 0.05 门槛的 probe | 13/16 | 13/16 |
| 4 个 greedy 样例，各 3 次、64 token | 全部一致 | 全部一致 |

每个模型执行原 300 条合成请求 3 次，实际 batch64 forward 各 342 次；逐条对照固定 16 个 probe，各重复 3 次。重复一致性结论覆盖每个 probe 保存的首 token 全词表 logits 和前 8 个固定目标 token logprob。另有 4 个原生单条 baseline probe 各 3 次，全部保留。合成输入不含正式任务题目。

13 组 GDN（包含 bs=1/2/64、多 token、history 和非恒等 slots）各重放 20 次，输出与状态全部逐位一致。相对原算子最大状态相对 L2 为 2.45334e-8，最大输出相对 L2 为 3.16110e-7。融合 MoE 固定输入重放 20 次也全部一致，相对原输出最大相对 L2 为 4.80085e-8。GDN 两处归约参照上游 900cf17；MoE 采用 1c8aff4 的独立槽位与固定顺序 gather 设计，适配旧 ABI，原量化 GEMM 二进制继续使用。

量化保护：原 EXL3 包 322 个文件逐文件对照全部未改；量化器、校准流程、码本、trellis、scale、权重解码和量化 GEMM 均保留。S0 与 S1 seed 0 的全部模型文件哈希均在运行前后核验；原冻结评测运行时及输入 seal 也通过。补丁只在明确开启的推理上下文生效，退出后恢复原函数；含梯度调用被拒绝。

独立 CPU 审计重算 504 个比较，跨 batch 相对 L2 使用原门禁的“单条 logits 范数”作分母。原 worker 通用比较函数以第一个参数作分母，原始文件保留；以 audit.json 为冻结门槛的正式重算。保存 logits 重新计算首目标 logprob 的最大误差不超过 1.021e-6。可移植版本通过 3 个 GPU 单元测试，并直接用于 S1 seed 0 验证；与本地 S0 验证版的补丁函数 AST 和 CUDA 源码完全一致。

S1 seed 1 没有完整最终模型（历史训练记录 221/256 步），在加载前被完成性检查拦住，失败记录保留。没有用中间模型替代。

边界：固定累加顺序会改变浮点舍入，因此不能承诺与旧版 greedy 文本或任务准确率完全相同。本次验证证明量化表示与流程未被改写、算子公式数值接近和所测重复性改善；未进行新的 cs6 质量验收或 G2a/G2b 全面重验。原失败预检与容差均保留。没有调整 Attention 调度或跨 batch 计算策略。

机器可读汇总见 [issue353-validation.json](issue353-validation.json)。原始诊断记录保留在实验工作区；本仓库不包含模型权重或评测输入。
